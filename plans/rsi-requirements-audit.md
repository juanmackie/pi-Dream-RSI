# Repository-level RSI requirements audit

This audit checks the implementation currently present in the shared working tree. It distinguishes usable local loop behavior from the additional guarantees requested for this goal. “Implemented locally” does not mean independently validated.

| Requirement | Current evidence | Status against this goal |
|---|---|---|
| Point a loop at a project and discover measurable bottlenecks | `extensions/pi-dream-rsi/engine/recon.ts`, `extensions/pi-dream-rsi/engine/metrics.ts`, `extensions/pi-dream-rsi/engine/loop.ts`; cold-start fixture proves a Node run, recon fixtures cover Python, Rust, Go, JVM, .NET, Swift, Elixir, PHP, Ruby, and Make-declared workloads, and attribution tests follow local Rust modules, Go module imports, and JVM class imports. | Partial. It discovers conventional test gates and explicit benchmark/test scripts, but “any repository” remains bounded by supported manifest/command detection and operator-declared outcomes; it does not synthesize a trustworthy performance outcome when the repository has no declared workload or evaluator. |
| Admit only measurable and budget-feasible projects, with a diagnosis | Run contract approval, instrument stability/sensitivity/oracle checks, durable process/evaluator budgets, and an up-front worst-case evaluator-run estimate for qualification plus promotion. The loop passes its live remaining allowance; an infeasible instrument returns a budget diagnosis before starting evaluator processes. | Partial. Run-count admission is implemented locally; evaluator-time and host-side helper costs are not fully predicted, and safety admission is only trusted-local consent, not sandbox admission. |
| Typed, allowlisted edit actions | Campaign application uses a typed write/delete patch path; optimizer generations now accept only four named research-policy artifacts and reject tests, evaluators, package metadata, reviewer prompts, and runner code. Active generations are content-checked and passed into the next campaign: method code seeds its isolated runtime, and discovery, development, and research-org prompts are pinned in the campaign snapshot. | Partial. A child agent remains a host process, not an actor limited to the patch API; the current trusted-local execution mode cannot prevent arbitrary host tool use. |
| Persistent provenance ledger | `extensions/pi-dream-rsi/engine/ledger.ts` appends sanitized JSONL records linked by SHA-256 record hashes; typed provenance records contract, instrument, baseline, mechanism and parent campaign; typed parent-event ids link attempts to confirmations, then gates/reviews to applies. Forward or missing parent references are rejected. An interprocess lock serializes writers. A separate `.head.json` checkpoint records the byte length, file digest, entry count, and terminal record identity, while `.head.required` prevents a missing checkpoint from silently downgrading the log to a legacy ledger. Readers reject corrupt, incomplete, edited, or shortened history. A writer can recover one complete record written before a crash interrupted its checkpoint update. A full 2,000-record ledger is readable with further appends refused. | Partial. The checkpoint detects ledger-only tail deletion and edits but is not an external witness. Coordinated rewriting or deletion of both the ledger and its checkpoint can still erase history. A process crash can leave a stale lock that requires manual removal after the wait timeout. The local campaign DAG does not yet include policy-search branches and external reviewer-guided research nodes. |
| Hidden oracle and hidden-split confirmation | Generation admission now requires an Ed25519 evaluator receipt bound to the staged artifact digest, evaluator identity, split identity, score/cost evidence, hidden regressions, per-canary results, and fresh-process reproduction. Canary ids and seed commitments must recompute to a host-pinned manifest digest. Receipt and split ids are single-use in the generation state. | Partial. This authenticates a host-pinned evaluator report; it does not prove that the signer is independent or that the evaluator actually ran a hidden suite. No production evaluator, host key/manifest configuration, hidden oracle, or unseen-repository split is configured. |
| Mutation, property, and differential oracles | When no known-better control patch is available, instrument qualification runs up to two deterministic comparison, numeric, or boolean mutants in disposable source copies and records which declared gates kill them. Each mutation run is charged through the evaluator reservation callback. | Partial. Mutant outcomes are diagnostic because valid performance edits can change runtime-only comparisons/constants while preserving correctness; independent evaluator/gate qualification and post-apply confirmation remain blocking. Property-based and generated differential oracle suites are not implemented. |
| Seeded canary cheats | Version 2 signed confirmation requires one detection result for each member of a host-pinned manifest. Each public canary id is deterministically derived from its seed commitment; aggregate-only counts and substituted commitments cannot be accepted. | Partial. A local signature fixture tests commitment binding and rejection of missed canaries, but there is no evaluator-side seed vault/registry, candidate-facing cheat suite, or 100% independent detection result. |
| Cost accounting | Durable budgets count agent starts, evaluator runs, campaigns, and deadlines. The append-only ledger records each agent-start reservation and per-process input/output/cache tokens and elapsed time for probe, discovery, review, and policy-development agents; repository evaluator/gate time is also recorded, and paired before/after confirmation events count both evaluator runs. A real accepted-candidate campaign test asserts reservations match the durable process counter and that probe/discovery/review process evidence is present. | Partial. Provider/model price schedules, machine/energy costs, and per-arm tournament totals are not configured; unrelated host-side helper work is not metered. |
| Fresh-context restart with inherited notes | Agent calls are separate processes; loop memory stores notes and interrupted-phase reconciliation charges reserved work. | Implemented for local loop restarts. This does not establish isolated execution. |
| Improve research policy from successful trajectories on sealed repo population | The generation engine rejects bare numeric promotion evidence and requires a single-use signed evaluator receipt before activation, and rechecks artifact allowlist/content identity in a fresh process. Distillation accepts host-signed lever and workflow evidence from a disjoint development population; the workflow schema searches bounded role/instruction/contract/DAG variants and emits only one-edit neighbors from independently winning profiles. A candidate still needs the separate hidden-split confirmation receipt before activation. | Partial. No real signed development corpus, production confirmation service, or independent judge is configured. Workflow priors are passed through the live research-org prompt, but the campaign runner still owns its phase schedule; an external tournament must demonstrate that the learned workflow changes outcomes. |
| Sandbox containment, no self-deployment, no exfiltration | `LoopOptions.containment` now covers recon probes, qualification evaluators and gates, baseline capture, campaign scoring, candidate confirmation, post-apply checks, and campaign probe/live/development/review agents. Repository commands and agent processes receive disposable workspaces as their only writable roots, no network egress, secret-key environment variables are removed, and PATH/runtime directories are read-only by default. The dream-phase agent gets a temporary workspace containing only its staged method file; campaign history and policy APIs are read-only mounts. Managed agent runs use MXC process handles for stdin, output, PID ownership, timeout, and abort cleanup. Windows canaries verify that an allowed shell and write run, while host-file reads, writes outside the workspace, loopback requests from an executable curl client, and secret-environment access fail. Agent-containment preflight also launches `node.exe --version` inside MXC. | Partial. The portable Node 24.21 runtime still exits with `STATUS_DLL_INIT_FAILED` inside this host's BaseContainer session, so preflight refuses before recon. MXC [issue #1465](https://github.com/microsoft/mxc/issues/1465) reports the same USER32-dependent workload failure from non-interactive Windows sessions. A remote-model broker is not implemented, and no-egress agents cannot reach a remote provider. Policy runtime code and host-side preparation are not inside a separate service boundary. No full autonomous no-exfiltration claim is established. |
| External tournament and reference home benchmarks | `eval/tournament/preregistration.mjs` validates the seven-arm protocol, held-out repo and policy splits, per-repo budgets, statistical gates, canaries, command digests, ablations, home benchmark mappings, and external registration. `eval/tournament/runner.mjs` is a fail-closed controller for pinned sandbox/evaluator adapters: one cumulative run per repo/arm emits four checkpoints, hidden judging runs separately, and the evaluator signs the final report. `eval/tournament/results.mjs` audits the signed report and computes paired bootstrap/Holm dominance results. | Partial. No real registry receipt/key, sealed repositories/benchmarks, sandbox/evaluator adapter bundles, runnable arm implementations, or source home-benchmark environments are present. The controller protocol is locally tested but the tournament has not been preregistered or run. See [tournament readiness](rsi-tournament-readiness.md). |

The current local loop has meaningful measurement, admission, budget, restart, ledger, and independent remeasurement machinery. It still falls short of the user’s requested security boundary, typed action surface, sealed repo-population policy evolution, canaries, and external proof. Those gaps must remain explicit until the underlying mechanisms and independent evidence exist.
